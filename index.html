Built a local Figma connection and ownership protocol with Codex. Planning can proceed in parallel, while editing and export require one owner. A unique claim, heartbeat, and explicit release prevent an old session from releasing a new session’s lock.

Codex로 로컬 Figma 연결과 사용권 제어를 구축했습니다. 기획은 병렬로 진행하되 편집과 내보내기는 한 세션씩 수행합니다. 고유 식별자와 사용 상태 갱신, 명시적 반납으로 이전 세션이 새 작업의 잠금을 해제하지 못하도록 했습니다.

In an isolated test, 1 of 12 concurrent requests acquired the lock. Applied to design work; this is a cooperative session protocol, not an OS-level lock.

격리 검증에서 동시 요청 12개 중 1개만 사용권을 획득했습니다. 실제 디자인 작업에 적용한 협력 프로토콜이며 OS 수준의 잠금은 아닙니다.

Verifying a cleanup job beyond the happy path 독립 검수로 확인한 사진 정리 작업의 처리 누락

I defined the preservation policy and review scope. Independent AI review found that protected photos could repeatedly consume a cleanup job’s limit, starving ordinary deletion candidates. The implementation session added a Redis scan cursor.

보존 정책과 검토 범위를 정하고 독립 AI 검수를 진행했습니다. 보호 대상 사진이 매번 처리 한도를 소진해 일반 사진의 정리를 막는 문제가 발견됐고, 구현 세션에서 Redis 순회 커서를 추가했습니다.

Isolated MySQL, Redis, and local S3 substitute: 7 protected photos + 1 ordinary photo, with deletions of 0, 0, then 1 across three runs. Production-wide behavior was not inferred from this test.

격리된 MySQL, Redis와 로컬 S3 대체 환경에서 보호 사진 7개와 일반 사진 1개를 검증했습니다. 세 차례 삭제 결과는 0건, 0건, 1건으로 보호와 정리를 함께 확인했습니다.

AI features and release operations

제품 AI 기능과 출시 운영

  • Review translation: versioned caches using the source hash and prompt version; no DB connection held while waiting for the model. Bounded concurrency and a 12-second timeout constrain resource use.
  • Applied canary deployment and Prometheus/Grafana monitoring. Distinguished OTA updates from native rebuilds, and checked the actual store submission artifacts.
  • For additive schema changes, separated the migration from the feature rollout to account for API migration execution and batch schema validation.
  • 리뷰 번역은 원문 해시와 프롬프트 버전으로 캐시를 관리합니다. 외부 모델 호출 중 DB 연결을 점유하지 않으며 동시 호출 제한과 12초 타임아웃을 적용했습니다.
  • 카나리 배포와 Prometheus 및 Grafana 관측을 적용했습니다. OTA 업데이트와 네이티브 재빌드를 구분하고 실제 스토어 제출 산출물을 확인했습니다.
